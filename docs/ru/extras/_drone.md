# Описание модуля дрона

Клиент дрона лежит в папке `drone/` и запускается файлом `client.py`. Он работает поверх ROS (Clover) и MAVROS. Эта страница — для тех, кто хочет понять, как клиент устроен внутри. Если вам нужно только пользоваться, смотрите [Работа с дроном](../drone.md).

## Структура

```
drone/
├── client.py            # точка входа, сетевая часть
├── update.py            # обновление клиента
├── config.example.ini   # шаблон настроек
└── modules/
    ├── animation.py     # разбор и подготовка анимации, выполнение кадров
    ├── checks.py        # проверка перед полётом
    ├── commander.py     # очередь задач (TaskManager)
    ├── config.py        # чтение drone.ini
    ├── failsafe.py      # аварийная посадка при потере позиции
    ├── flight.py        # полётные команды через сервисы Clover
    ├── led.py           # управление лентой
    ├── network.py       # время: chrony и NTP
    ├── remote.py        # файлы, команды и сервисы по запросу сервера
    ├── utils.py         # имя дрона, логирование
    └── version.py       # версия клиента
```

## client.py

При старте клиент:

1. создаёт ROS-ноду `drone_swarm_client`;
2. берёт имя дрона из `hostname` — это `copter_id`;
3. читает `drone/drone.ini`;
4. создаёт `TaskManager` (выполняет команды) и `Watchdog` (аварийная защита), который проверяется каждые 0.5 с;
5. запускает сетевой слой — четыре потока.

Сетевой слой — класс `NetworkManager`. Его потоки:

| Поток | Период | Что делает |
|---|---|---|
| команды | постоянно | ищет сервер по UDP-широковещанию, подключается по TCP, принимает и выполняет команды |
| телеметрия | 0.5 с | отправляет состояние серверу по UDP |
| проверка | 5 с | запускает `checks.self_check()` |
| время | 5 с | измеряет расхождение часов |

### Протокол

Все сообщения — JSON.

**Поиск (UDP, порт 9000).** Клиент шлёт широковещательный запрос, сервер отвечает:

```json
{"type": "discover", "copter_id": "clover-1"}
{"type": "discover_reply", "tcp_port": 9010}
```

**Команды (TCP).** Каждое сообщение: 4 байта длины (big-endian) + JSON. Клиент сначала отправляет приветствие, потом получает команды:

```json
{"type": "hello", "copter_id": "clover-1"}
{"action": "takeoff", "params": {"height": 1.5}}
{"type": "log", "text": "config updated (modify)"}
```

Последнее — ответ клиента: текст попадает в консоль сервера.

**Телеметрия (UDP, порт 9001).** Один JSON со всеми полями: `copter_id`, `version`, `x/y/z/yaw`, `frame_id`, `bat`, `armed`, `mode`, `connected`, `states` (состояние каждой колонки: `ok`/`warn`/`fail`), `animation_id`, `animation_state`, `start_pos`, `checks`, `config`, `errors`, `time_offset`.

### Команды сервера

| Команда (`action`) | Параметры | Что происходит |
|---|---|---|
| `check` | — | запускает проверку в отдельном потоке |
| `set_config` | `ini_text`, `mode` (`modify`/`rewrite`) | записывает `drone.ini` и перечитывает настройки |
| `set_animation` | `csv_text` | записывает `animation.csv` и перезагружает анимацию |
| `write_file` | `path`, `data` (base64), `restart` | записывает файл, при необходимости перезапускает сервис |
| `run_command` | `command` | выполняет shell-команду |
| `restart_service` | `name` | перезапуск `chrony`, `ros` или `swarm` |
| `reboot` | — | перезагрузка системы |
| `load_fcu_params` | `path`, `data` | сохраняет файл и загружает параметры в PX4 через `rosrun mavros mavparam` |
| `play`, `takeoff`, `land`, `stop`, ... | зависят от команды | передаются в `TaskManager` |

Если моторы дрона запущены (`armed`), клиент отказывается от `reboot`, перезапуска сервисов (кроме `chrony`) и замены анимации. Команда `play` не выполняется, пока последняя проверка не пройдена (если в параметрах нет `ignore_checks`).

> Канал команд не защищён: сервер может выполнить на дроне любую команду. Это сознательное упрощение для закрытой сети шоу.

## modules/commander.py

`TaskManager` выполняет **одну задачу в каждый момент**. Метод `do_action()` сначала поднимает флаг `interrupter`, ждёт до 2 секунд, пока текущая задача остановится, а затем ставит в очередь новую. Все циклы ожидания в `flight` и `animation` проверяют этот флаг каждые 0.05–0.2 с, поэтому посадка или пауза прерывают всё остальное.

Функция `_play_animation()`:

1. требует `animation.state == "OK"` и известную позицию в `aruco_map`;
2. выбирает действие: `takeoff` или `fly` (см. [модуль анимации](animation.md));
3. если задан `start_time`, переводит его в локальное время с учётом расхождения часов и ждёт;
4. идёт по кадрам: ждёт момента кадра и вызывает `execute_frame()`.

## modules/flight.py

Тонкая обёртка над сервисами Clover: `navigate`, `land`, `get_telemetry`, `mavros/cmd/arming`, `mavros/cmd/command`.

* Все полёты идут в системе координат `aruco_map` (`FRAME_ID`).
* `navto()` — не блокирует: отправляет точку и сразу возвращается. Нужен для кадров анимации, чьё время задаётся расписанием.
* `reach_point()` — блокирует, пока дрон не прилетит (допуск 0.2 м) или не истечёт время (20 с).
* `takeoff()` — летит вверх относительно `body`, потом проверяет высоту в `aruco_map`.
* `land()` — вызывает посадку и ждёт дизарма; если прошло время и высота ниже 0.3 м, принудительно останавливает моторы.
* `stop()` — задаёт цель в текущей позиции, то есть зависание.

## modules/checks.py

`self_check()` возвращает `{"ok": bool, "problems": [...], "warnings": [...]}`. Проверки: FCU, батарея, видимость карты ArUco, доступность сервисов ROS (`navigate`, `land`, `get_telemetry`, `led/set_effect`). Батарея считается на одну банку; предупреждение появляется только если проблем нет. Функция `battery_state()` используется и для колонки `battery` на сервере.

## modules/failsafe.py

`Watchdog` подписан на позицию `mavros/vision_pose/pose`, состояние FCU и дальномер.

* Если дрон армирован, в режиме `OFFBOARD`, и позиция не обновлялась дольше 2 секунд, включается режим `AUTO.LAND`.
* Состояние `sensors_ok()` — свежесть позиции независимо от того, летит дрон или нет (колонка `sensors`).
* `rangefinder_ok()` — приходят ли данные дальномера (даёт жёлтый цвет колонки).

## modules/remote.py

Служебные действия по запросу сервера: запись файла (атомарная, с `sudo tee` для системных путей), слияние `.ini` в режиме `modify`, выполнение команды (таймаут 60 с, вывод обрезается до 4000 символов), перезапуск сервисов. Имена сервисов сопоставляются так:

| Имя в меню сервера | Сервис systemd |
|---|---|
| `chrony` | `chrony` |
| `ros` | `clover` |
| `swarm` | `droneswarm` |

## modules/network.py

Работа со временем. `get_time_offset()` сначала спрашивает `chronyc tracking`; если `chrony` не синхронизирован, пробует NTP-запрос к серверу. `set_chrony_server()` добавляет найденный сервер в `chrony` командой `chronyc add server`, поэтому IP в конфиге не нужен. Файл `chrony.conf` дрона (`makestep 1 3`) только разрешает быструю подстройку времени после загрузки.

## modules/version.py и update.py

Версия клиента — `ветка@коммит` (если стоит из git; звёздочка в конце значит, что есть локальные правки) или версия пакета `drone-swarm` (если стоит из apt). `update.py` выполняет `git pull --ff-only` либо `apt-get install --only-upgrade`, а затем перезапускает сервис.

## modules/utils.py и led.py

`utils.py` настраивает логирование: файл `<hostname>.log`, консоль и кольцевой буфер из последних 30 предупреждений и ошибок (он уходит на сервер). `led.py` вызывает сервис Clover `led/set_effect`; `test()` по очереди включает красный, зелёный и синий.
