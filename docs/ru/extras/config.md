# Конфигурация

У дрона и у сервера есть свои файлы настроек в формате `.ini`. Если файла нет или в нём не хватает параметров, используются значения по умолчанию. Неизвестные ключи и значения неверного формата записываются в лог и игнорируются, а остаётся значение по умолчанию.

Готовые примеры лежат в папке `examples/configs/`.

## Конфигурация дрона

Файл `drone/drone.ini` (рядом с `client.py`). Шаблон — `drone/config.example.ini`. Изменения применяются после перезапуска клиента либо сразу, если отправить конфиг с сервера: **Selected drones → Send → Configuration...** Там есть два режима:

* **Modify** — обновить только те ключи, что есть в отправленном файле, остальные оставить;
* **Rewrite** — заменить файл целиком.

> Если дрон в воздухе, он применит новые настройки анимации только после следующей перезагрузки анимации.

Активные настройки дрона видно на сервере: двойной щелчок по ячейке в таблице.

### [animation]

| Параметр | По умолчанию | Описание |
|---|---|---|
| `frame_delay` | `0.1` | время между кадрами в секундах, если в файле анимации не задано иное |
| `yaw` | `animation` | `animation` — брать угол из файла; число — фиксированный угол в градусах |
| `common_offset` | `0, 0, 0` | общий сдвиг анимации по X, Y, Z в метрах (для всех дронов) |
| `private_offset` | `0, 0, 0` | сдвиг только для этого дрона |
| `ratio` | `1, 1, 1` | масштаб по осям; применяется до сдвига |
| `takeoff_level` | `0.3` | высота (м), ниже которой дрон считается стоящим на земле |
| `output_static_begin` | `false` | играть ли начальный участок, где дрон стоит на месте |
| `output_takeoff` | `true` | играть ли участок взлёта |
| `output_route` | `true` | играть ли основной маршрут |
| `output_land` | `true` | играть ли участок посадки |
| `output_static_end` | `false` | играть ли конечный участок, где дрон стоит на месте |
| `check_ground` | `true` | проверять, что анимация не ниже земли |
| `ground_level` | `current` | высота земли: `current` — текущая высота дрона, или число в метрах |
| `start_action` | `auto` | как стартовать: `takeoff` — с взлёта, `fly` — сразу в полёте, `auto` — определить по первой точке |

Значения с координатами пишутся через запятую. Логические значения: `true`/`false`, `yes`/`no`, `on`/`off`, `1`/`0`.

Координаты кадра пересчитываются так: `x' = ratio_x · x + common_offset_x + private_offset_x`, и так для каждой оси. Так можно сдвинуть всё шоу или один дрон, не пересоздавая анимацию.

### [led]

| Параметр | По умолчанию | Описание |
|---|---|---|
| `use` | `true` | включить управление лентой |
| `takeoff_indication` | `true` | красная индикация при взлёте и зелёное мигание после |
| `land_indication` | `true` | мигание красным при посадке |

### [flight]

| Параметр | По умолчанию | Описание |
|---|---|---|
| `takeoff_height` | `1.5` | высота взлёта в анимации, м |
| `takeoff_time` | `5.0` | время на взлёт, с |
| `land_timeout` | `5.0` | время на посадку, с |
| `land_delay` | `0.0` | задержка перед командой посадки в конце анимации |
| `arming_time` | `5.0` | время на запуск моторов перед началом полёта |
| `reach_first_point_time` | `5.0` | время, которое даётся дрону, чтобы долететь до первой точки после взлёта |

### [checks]

Напряжения указаны **на одну банку**: клиент делит напряжение батареи на `battery_cells`.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `battery_cells` | `4` | количество банок аккумулятора |
| `battery_min_voltage` | `3.5` | ниже — проверка не пройдена, колонка красная |
| `battery_warn_voltage` | `3.7` | ниже — предупреждение, колонка жёлтая |
| `fcu_timeout` | `3.0` | сколько ждать сообщения от полётного контроллера, с |
| `service_timeout` | `2.0` | сколько ждать каждый сервис ROS, с |

Пример для батареи 6S:

```ini
[checks]
battery_cells = 6
```

## Конфигурация сервера

Файл `server/config/server.ini`. Шаблон — `server/config/server.example.ini`. Править можно из меню **Server → Edit server config**; изменения применяются после перезапуска сервера (**Server → Restart server**).

### [network]

| Параметр | По умолчанию | Описание |
|---|---|---|
| `discovery_port` | `9000` | UDP-порт, на котором сервер отвечает на поиск |
| `telemetry_port` | `9001` | UDP-порт приёма телеметрии |
| `tcp_port` | `9010` | TCP-порт для команд |
| `bind_address` | `0.0.0.0` | на каком адресе слушать; `0.0.0.0` — на всех интерфейсах |
| `drone_timeout` | `5.0` | через сколько секунд без телеметрии дрон считается отключённым |

> Порт поиска (`9000`) жёстко прописан в клиенте дрона, а порт телеметрии клиент считает как порт поиска плюс один. Поэтому `discovery_port` и `telemetry_port` лучше не менять. `tcp_port` менять можно: сервер сообщает его дронам при поиске.

### [server]

| Параметр | По умолчанию | Описание |
|---|---|---|
| `log_dir` | `.` | папка для логов |

### [paths]

| `launch_dir` | `/home/pi/catkin_ws/src/clover/clover/launch` |
