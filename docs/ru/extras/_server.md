# Описание модуля сервера

Сервер лежит в папке `server/`. Это приложение на PyQt5: окно с таблицей дронов и сетевая часть, которая работает в фоновых потоках. Если вам нужно только пользоваться, смотрите [Работа с сервером](../server.md).

## Структура

```
server/
├── core.py                  # окно, таблица, меню, кнопки
├── config/
│   └── server.example.ini   # шаблон настроек
├── chrony/
│   └── chrony-server.conf   # конфиг chrony для компьютера с сервером
└── modules/
    ├── config.py            # чтение server.ini
    ├── network.py           # сеть: поиск, команды, телеметрия
    └── version.py           # версия сервера и git pull
```

## modules/network.py

Класс `NetworkManager` поднимает три потока. Они слушают порты, заданные в [конфигурации](config.md).

| Поток | Порт | Что делает |
|---|---|---|
| поиск | UDP 9000 | отвечает на `discover` сообщением `discover_reply` с TCP-портом |
| команды | TCP 9010 | принимает подключения дронов, читает приветствие `hello` и ответы `log` |
| телеметрия | UDP 9001 | принимает JSON с состоянием дрона и передаёт его в окно |

Формат сообщений описан в [описании модуля дрона](_drone.md#протокол).

Особенности:

* для каждого дрона создаётся свой объект `DroneConnection` со своим потоком отправки и очередью. Зависший дрон не блокирует окно и команды другим;
* если дрон с тем же именем подключается снова, старое соединение закрывается;
* сокет включает `TCP_NODELAY` и `SO_KEEPALIVE`;
* если не удалось отправить сообщение целиком, соединение закрывается: частично отправленный кадр испортил бы поток. Дрон сам найдёт сервер заново;
* в телеметрию добавляются `_last_seen` (время получения) и `_addr` (IP дрона);
* `send_command()` отправляет команду одному дрону, `broadcast_command()` — списку. Если соединения нет, команда не уходит, а в консоль пишется предупреждение.

В окно данные передаются через сигналы Qt: `telemetry_received`, `drone_disconnected`, `log_message`.

## modules/config.py

Читает `server/config/server.ini` и подставляет значения по умолчанию, если ключа нет. Ключи объединяются как `раздел_ключ`: параметр `tcp_port` из раздела `[network]` доступен как `config.network_tcp_port`. Полный список параметров: [Конфигурация](config.md).

## modules/version.py

`get_version()` возвращает `ветка@коммит`, а звёздочка означает локальные изменения. Сервер сравнивает эту строку с версиями дронов в колонке `version`. `git_pull()` выполняет `git fetch` и `git pull --rebase`.

## core.py

Основной класс — `DroneDashboard`.

**Таблица.** Одна строка на дрона, колонки перечислены в [описании сервера](../server.md#таблица-дронов). Состояние каждой ячейки считается в `update_row()`:

* `version_state()` — версия совпадает с серверной;
* `animation_state()` — анимация загружена и имеет название;
* `dt_state()` — расхождение часов (< 0.05 с — `ok`, < 0.2 с — `warn`);
* `start_state()` — расстояние от текущего положения до начальной точки анимации (≤ 0.3 м — `ok`, ≤ 1 м — `warn`);
* остальные состояния (`battery`, `system`, `sensors`, `mode`, `position`) приходят от самого дрона в поле `states`.

Строка считается отключённой, если нет TCP-соединения или телеметрии больше `drone_timeout` секунд (таймер `check_stale`).

**Отправка файлов.** Анимации, калибровки и другие файлы читаются на сервере и отправляются дрону внутри команды в виде текста или base64. Для папок (`Animations...`, `Camera calibrations...`) файл для дрона ищется по имени: в имени файла должен быть `copter_id` как отдельный фрагмент. То есть `clover-1.csv` подойдёт дрону `clover-1`, но не дрону `clover-10`.

**Обновление.** Пункт **Update** отправляет дрону `run_command` с одной shell-командой: `git pull --ff-only`, если на дроне есть git-копия, иначе `apt-get install --only-upgrade drone-swarm`; потом через 3 секунды сервис `droneswarm` перезапускается. Благодаря этому можно обновить и дроны со старой версией клиента.

## Что не реализовано

* **Play music** и **Визуальная посадка** — заготовки без логики;
* **Flip** отправляет команду, но клиент её игнорирует.
